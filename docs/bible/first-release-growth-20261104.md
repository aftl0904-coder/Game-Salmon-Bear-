# 第一版五軸成長（2026-11-04）

基於 main `077af8b14b34b3e26d776e36705772fdd691639b`。Alan 的最新補充見 [first-release-confirmations-20261104.md](first-release-confirmations-20261104.md)；與舊提案有衝突時，以最新確認為準。以下是已確認規則，**並不代表此 draft 已經在遊戲實現；不可合併或部署**。

## 已確認規則

- 第1關或第6關開新局，倫寶、琪寶寶各有 5 個起始點，可分配五軸或留待日後分配。起始 5 點不是舊成長，不影響榜單資格。
- 選擇帶舊成長：承接所選舊局的角色成長，每角色至少有 5 點可重新分配，但不是舊點額外加 5；舊有 10 點仍是 10。實際帶入非零舊成長或舊裝備，該局不入排行榜。選不帶：當局各 5 點，舊資料仍須保留。
- 舊局成長要有可操作的選取和取回方式；每局保存獨立、不得把不同局點數相加。選回舊局作新局來源時承接單一所選成長，不可只藏成玩家無法存取的備份。舊局的發點 provenance 必須同時保留。
- 第3、5、7關按既有 `clearRank()`：S＝3、A＝2、B＝1、C＝0；主線按順序首次通關時**兩位角色各得同額**，不論單人或雙人。每局每關只發一次；另一新局可按自身首次順序過關發點。支線／重玩不發、不改主線。
- 商店免費重配已取得點數，不得增加總點、跨角色轉點或破壞支線隔離。永久成長死後保留；裝備是臨時層，死亡清零。原有 S 評級無死亡、生命／裝備跨關延續和榜單規則不變。
- 直接選非第一關、跳關或重玩按既定基準支線，不帶舊成長與裝備；基準本身可上榜。舊主線／舊裝備首次遷移視為同局延續，不自動取消榜單資格。損壞、未知資料或寫入失敗不得靜悄悄覆寫。

## 本 draft：隔離模型 checkpoint，尚未接線

`src/game/growth.ts` 包含純點數與每局 `GrowthBook` 模型：分角色錢包、起始來源及領獎紀錄、按順序發獎、重複事件無效、支線不改模型、選一份舊成長開新局、免費重配及嚴格驗證。`scripts/qa/first-release-growth-ledger.mjs` 是純模型測試。帳本**尚未放入 `run.ts` 存檔**，玩家不能開啟成長 UI 或取回舊成長，遊戲不會發點，也沒有五軸戰鬥效果。

舊版 `run.ts` 的 `growthOf()` 僅認頂層數字，不能直接儲存巢狀帳本。模型只允許空的舊預留欄位按零點遷移；非空或未知格式拒絕並保留原文，暫不猜測如何轉換。這是候選遷移策略，並非已在玩家舊檔執行。

重要接線風險：目前 `GameScene.win()` 呼叫 `saveCurrentClear()` 先推進存檔，`buildClearCard()` 其後才算評級。接線時必須把與畫面相同的評級提前計算，並將進度、評級及雙人發點 ledger 放入**同一個本局快照**寫入，不能先保存通關再補記獎勵；要處理中斷、重複事件、寫入失敗與跨分頁陳舊資料。現有 localStorage 比對再寫並非跨分頁原子操作，不能聲稱已解決同時寫入競態。

## 數值草案：未接線、未經實戰平衡

以現行程式 `MAX_HP=6`、普通攻擊 3、絕招基礎 3、耐力上限 1／回復 0.55 每秒、受擊無敵 1500ms 為參考，以下只供候選估算：

| 每點 | 候選增幅 | 限制及接線注意 |
|---|---|---|
| 生命 | 上限 +0.5 格 | 先處理半格 HUD、治療、跨關 HP 及復活 |
| 攻擊 | 傷害 ×(1 + 0.10 ×點數) | 與武器、Boss 及取整次序須一併測試 |
| 防禦 | 減傷 5%，無敵 +30ms | 減傷最多 40%，額外無敵最多 500ms，最少扣 1 格；跌坑及 S 規則不變 |
| 耐力 | 上限 +10%、回復 +3% | 與鞋及符倍率相乘需驗證 |
| 絕招 | 傷害 +0.2 | 保留原有符及裝備效果 |

單局假設 14 點集中於單軸：生命 +7、攻擊 ×2.4、防禦減傷上限 40%／無敵 +420ms、耐力 ×2.4／回復 ×1.42、絕招 +2.8。不是已批准總上限；極端攻擊及生命可能過強。這些不是已驗收平衡值；須驗證五軸實際戰鬥、極端配點及裝備交互，不能聲稱已真人手感驗收。
