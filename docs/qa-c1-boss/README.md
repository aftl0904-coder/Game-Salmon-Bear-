## 舊測試：假陽性和原始失敗（歷史紀錄）

**後續單獨手機重測仍失敗**：以已加強起點、落地中心及站位斷言的腳本重新測 `mobile-boy-worst`、`mobile-girl-worst`，兩個起點均正確，但均受羽毛傷害 1 血；預警約 2483／2417ms。目標分別是 x=3285／3490，實測最後 x=3202／3389，均超出預定安全位置。測試控制／模擬負載還是遊戲可避性的原因未釐清，不能宣稱手機安全通過。原始紀錄 `mobile-recheck.log`、`run-mobile.json`。本次 shell 在手機測試失敗後因 `PIPESTATUS` 變數錯誤提早退出，原訂 2P 單獨重測**未執行**；此 shell 錯誤不是遊戲錯誤。已關閉本次伺服器。

`auto.log` 寫出的 PASS **不等於全部驗收成功**。回查 `run.json` 逐幀位置後發現：手機 boy 最後在 x=3164（坑 3160–3200），手機 girl 最後在 x=3267，而非原定 x=3490；2P 第二名角色首筆取樣已被遊戲拉到 x≈3208，與注入的 x=3588 不符，亦未走到原定 x=3490。腳本當時只比較血量／方向，沒有嚴格確認雙人初始位置、抵達後停留位置及坑邊落腳，故上述手機和 2P 的 PASS 是**無效證據，均未通過驗證**；不能據此聲稱純 touch 或分開站位的 2P 公平度已驗證。取樣低頻及執行環境負載造成大幅過衝；確切原因仍待獨立調查。

保留所有原始 `auto.log`、`run.json`、截圖和 `initial-run.log`，不刪改失敗。初輪桌面 boy 失血及手機等待羽毛逾時：擷取截圖期間遊戲仍在運行，確切失敗原因未被充分隔離；後一輪取消走位期間截圖，不代表證明首輪失敗的根因。之後已加強腳本，要求注入位置正確、持續站在預定安全地面，以及接近落地時的碰撞中心；**後續只重跑手機且失敗，2P 新斷言仍未重跑**，不得把舊 log 當成已通過新腳本。原始畫面僅作診斷；初輪截圖過程的時間不屬正常反應量度。
