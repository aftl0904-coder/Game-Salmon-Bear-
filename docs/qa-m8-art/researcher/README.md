# 第8關：主任研究員 Boss 動畫初稿 QA

`public/art/stage8/enemies/s8researcher-draft.png` 為待審素材，1720×816，10 欄×4 行共 40 格；每格 172×204、res2，邏輯格 86×102。相鄰 `.json` 記錄以下十組各四格及建議速度；尚未接入遊戲：idle、舉板預警、橫掃、拋瓶預警、拋瓶、補瓶、發光弱點、受傷、倒下、停輸出／交板。`gifs/` 是對應動畫預覽，供檢查，不代表遊戲設定必定循環。

橫掃已加入彎曲軌跡，補瓶由瓶向腰袋放下，弱點發出變化的亮光；但橫掃手臂仍較像直推，補瓶最後瓶頸很小，動作轉場與正常速度仍須覆核。拋瓶中兩格已畫入飛瓶及動線，人物水平位置分別偏移約 3／15 邏輯 px；如 Cursor 接入獨立投射物須避免重複顯示，亦要檢查跳動。停輸出／交原稿只有伸手及遞空白板；必須由遊戲控制台狀態和交接場景配合，角色圖本身不證明動作完成。

沿用第7關 Boss 每格 172×204、res2：本體待機高約 **71 邏輯 px**，在 scale 1 不符合風格文件 Boss 128px+。理論整數 scale 2 可達約 142px，但場景比例、碰撞及錨點尚未實測，不代表已通過 128px 驗收。`anchorX`／`anchorY` 只屬交接資訊，未證明會由現有框架自動使用。

原圖及局部重畫均從大圖大幅縮小，不是目標尺寸原生繪製；先二值化、沿透明間隙切格，刪除低 alpha 邊緣，縮放／量化有損失，未證明外框處處為 1px。實際來源、切線、縮放及量化量度見 `source-qa.json`；其中 `/tmp` 路徑只記錄來源，不代表已入庫。

第一次檢查發現生成 atlas 是 PNG palette mode `P` 而不是所需 RGBA，失敗原紀錄保留 `image-check-initial.json`。之後已轉成 RGBA，逐像素解碼比較確認內容不變；`image-check.json` 重測 40 格均有內容、四邊透明、alpha 0／255、全 atlas 64 個可見色。

`browser.txt`、`desktop-*.png`、`mobile-touch-*.png` 為桌面滑鼠及模擬手機純 touch 的十組動作獨立預覽；不是遊戲、真人或真機測試。`build.txt` 為 tsc + Vite，`validate-data.txt` 為 10 項資料驗證，均通過；既有 Vite 大 chunk 警告仍在。實際弱點碰撞、場景比例、轉場、交原稿、正常遊玩速度及真機全部未驗證。
